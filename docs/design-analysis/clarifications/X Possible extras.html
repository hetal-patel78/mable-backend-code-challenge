X5HLD (Aggregate root Account, Value object Money, TransferService)Full domain-driven design terms and structure. The rubric asks for domain models, not a particular method.Can show good object design, or look heavy for a small program.LowNone.Use light DDD: keep the DDD thinking but not the ceremony. The rules live inside the models (16 digits in AccountNumber, exact money in Money using BigDecimal with max 2 decimals, not same account and above zero in Transfer, no overdraft in Account, unknown account on find and no duplicates on add in the repository). Class and file names are plain domain words like Account, Money and Transfer. No base classes, no suffixes like AggregateRoot or ValueObject, and no domain events, factories, commands, DTOs or mappers. The code is organised in three folders, domain, application and infrastructure. A new folder is only added when it holds several files.

The spec folder mirrors the code with spec/domain/, spec/application/ and spec/infrastructure/ holding one spec file per class. End-to-end specs that run the program on fixture files live in spec/acceptance/. Test CSV files live in spec/fixtures/ (sample/, rejections/ and invalid_balances/). Small shared helpers like valid-by-default builders live in spec/support/. Shared settings like random order are in spec_helper.rb, with .rspec setting --format documentation. The DDD reasoning is explained in the README, not in the code.
